# v0.6 Terraform Destroy and Cleanup Validation

## Status

**PASS**

Validation time: 2026-08-31 UTC / 2026-08-30 EDT

This record closes the Terraform lifecycle for the event-driven test stack. The six Terraform-managed resources were destroyed through a saved destroy plan, then checked through Terraform state, the Floci APIs, and Docker.

The manually created reference stack was checked before and after the destroy and remained present.

This record is sanitized. It does not include the private VM address, Terraform state, saved plans, mapping UUIDs, message IDs, container IDs, or the raw command log.

## What was removed

Terraform managed exactly these six resources:

```text
DynamoDB table:       FlociTerraformOrders
SQS queue:            floci-terraform-orders
IAM role:             floci-terraform-orders-role
IAM inline policy:    floci-terraform-orders-policy
Lambda function:      floci-terraform-orders-processor
Event-source mapping: SQS to Lambda
```

Before planning the destroy, the script checked that the managed Terraform state contained exactly those six resources.

Observed assertion:

```text
TERRAFORM_MANAGED_STATE_PRE_DESTROY=PASS
```

The three Terraform data resources were listed separately and were not counted as managed infrastructure.

## Destroy plan

Terraform produced:

```text

```

The script compared the destroy set against the exact expected six managed resource addresses before allowing the saved plan to be applied.

Observed assertions:

```text
TERRAFORM_DESTROY_PLAN_EXACT_MATCH=PASS
TERRAFORM_DESTROY_COUNT=6
```

## Saved-plan destroy

The saved destroy plan was applied successfully.

Observed result:

```text

TERRAFORM_DESTROY=PASS
```

The SQS queue took longer than the other resources to disappear, but Terraform waited until its deletion completed.
